## 方法

### 1. Student 结构（`student.py`，`configs/rope_w240_d6_h2_do05.json`）

在官方 GPT 基线上做的改动，每一项都有配置开关：

- **RoPE** 取代可学习的绝对位置编码。
- **窗口内 pointer / copy 混合**：除了词表分布，再用一个因果注意力头从本窗口已出现的 token 里复制，用门控把两种分布混合。WikiText 里专名、数字和罕见词很多，这一项收益最大。
- **SwiGLU** 前馈层，**RMSNorm + QK-Norm**，**门控注意力输出**。
- 宽 240、6 层、2 个头；embedding、注意力和残差分支都用 dropout 0.05。

### 2. 训练配方（`train.py`）

- batch 32 × 256，AdamW，lr 1.2e-3，100 步 warmup 后余弦退火，梯度裁剪 1.0。
- **EMA 0.99**，最终保存 EMA 权重。
- GPU 上前向和反向用 BF16 自动混合精度，参数、优化器和 EMA 都是 FP32；验证和测试打分全用 FP32。

### 3. 知识蒸馏

损失是 `0.3 × 交叉熵 + 0.7 × KL(teacher ‖ student)`，训练 40000 步。teacher 分布是两部分的概率混合：

- **0.7 × 8 模型加权集成。** 在验证集上用 EM 求最优混合权重（目标函数是凹的，EM 收敛到全局最优），再用前后两半交叉验证确认权重没有过拟合。成员包括几个 384/512 宽、8 层的大 Transformer，几个 240 宽的 student，以及第一代蒸馏 student。
- **0.3 × 4 折 out-of-fold（OOF）集成。** 把训练集按顺序切成 4 段，第 k 个 teacher 只在另外 3 段上训练，蒸馏时只给第 k 段里的窗口打标签。这样做的原因是：普通 teacher 在训练集上会"背答案"（训练集 BPB 约 0.96，验证集 1.36），直接蒸馏会把这种过度自信传给 student。OOF teacher 看到的都是没见过的数据，给的是更接近泛化能力的分布。

- 蒸馏权重 α（dropout 0.05）：0.5 → 1.4173，0.6 → 1.4112，**0.7 → 1.4092**，0.8 → 1.4130，0.9 → 1.4199。

- 蒸馏温度 T = 2（dropout 0.2，α 0.5）：1.4510，比 T = 1 的 1.4455 差。

## 做过但没带来提升的方向

### 结构多样的 teacher（`teacher_zoo.py`，`ngram_kn.py`，`ens_tools.py`）

为了让集成更多样，额外训练了 AWD 风格的 LSTM、Mixture-of-Softmaxes、MoE Transformer，并在 BPE token 上实现了修正 Kneser-Ney 5-gram。这些模型单体都不强（MoS 1.4465、LSTM 1.4650、MoE 1.4825、KN5 1.7604），但在集成里都拿到了明显权重：

| 集成 | 验证 BPB |
|---|---|
| 原来的 8 模型加权集成 | 1.3601 |
| 原来的 17 个模型 EM 加权 | 1.3584 |
| 加入 MoS、MoE、LSTM 后选出的 8 个神经网络模型 | 1.3489 |
| 全部 28 个模型（含 KN5） | 1.3453 |

贪心选择和两半交叉验证的完整输出见 `results/ensemble_selection_28models.txt`。

**但更强的集成几乎没有传给 student**：新 teacher 加 OOF 混合，30000 步是 1.3963，旧 teacher 是 1.3975；不混 OOF 时反而更差（1.4033 对 1.4008）。原因是蒸馏在训练集上进行，而新加入的模型在训练集上背答案更严重：

| teacher | 训练集 BPB | 验证集 BPB | 差距 |
|---|---|---|---|
| 旧 8 模型集成 | 0.9554 | 1.3599 | 0.405 |
| 新 8 模型集成 | 0.9171 | 1.3489 | 0.432 |
| MoE（最终 checkpoint） | 0.8916 | 1.5228 | 0.631 |
| LSTM-c | 1.0243 | 1.4696 | 0.445 |
| MoS | 1.2144 | 1.4465 | 0.232 |

结论：挑蒸馏 teacher 不能只看验证集，还要看它在训练集上的过拟合程度。更根本的办法是把这些结构也做成 OOF 版本，这一步没有做完。

### 其他记录

- **LSTM 一开始完全学不动**：embedding 用 GPT 的初始化（std 0.02），而 LSTM 输出被 tanh 限制、输出层又和 embedding 共享权重，于是 logits 和回传到 LSTM 的梯度都小了约三个数量级。把 embedding 初始化改成 std 0.1 后恢复正常。
- **RTX 5090 + PyTorch 2.7.1 上 FP32 的高效注意力内核不稳定**：同一输入跑两次输出相差约 0.1。BF16 内核、数学实现和 CPU 都正常。训练用 BF16 不受影响；GPU 上的 FP32 验证和缓存都强制改用数学实现（`train.py` 里的 `exact_attention`）。正式分数一直在 CPU 上算。
- 大 teacher 训练过久会过拟合：384 宽、dropout 0.2 的 teacher 在 8000 步是 1.4549，20000 步退到 1.4930。但过拟合的 teacher 在集成里反而权重很高，因为它们的预测更"锐利"。

## 训练成本

全部在单卡 RTX 5090 上训练（计时不含中途验证）：

- **最终提交的完整链条约 4.0 GPU 小时**（14,337 秒）：最终 student 5,230 秒，加上它依赖的 19 个 teacher 和 OOF 模型。
- **全部 92 次有记录的实验约 24.3 GPU 小时**，不含被中止的实验、集成分析和 CPU 打分。

## 复现

1. 安装依赖：`pip install -r requirements.txt`。
2. 把课程 starter 包里的 `data/` 目录（WikiText-2 原文、分词器、`manifest.json`）放到仓库根目录。数据不在本仓库里。
3. 运行 `bash scripts/reproduce_final.sh`。它按顺序训练 teacher、OOF teacher、第一代蒸馏 student 和最终 student，最后在 CPU 上用 FP32 打测试集。
